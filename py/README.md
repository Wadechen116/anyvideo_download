# AnyVideo Download — Python 版

貼上網址，把網路上的影音下載下來，存成你要的格式。

下載核心是 [yt-dlp](https://github.com/yt-dlp/yt-dlp)，格式合併與轉換由 ffmpeg 負責，
介面用 Python 內建的 Tkinter。

> 同一套規則另有 Qt 版（`..\qt`）與 C# 版（`..\csharp`），三個版本的差異見上一層的
> [README.md](../README.md)。這份文件的「支援的輸出格式」「取捨」「其他選項」「疑難排解」
> 三個版本都適用。

---

## 需要的東西

| 項目 | 用途 | 安裝 |
|---|---|---|
| Python 3.10 以上 | 執行程式 | <https://www.python.org/> |
| yt-dlp | 下載核心 | `py -3 -m pip install -r requirements.txt`（或程式裡按「更新下載核心」） |
| ffmpeg | 合併影音、轉換格式 | `winget install Gyan.FFmpeg` |
| deno（選配） | YouTube 需要它才能取得完整格式 | `winget install DenoLand.Deno` |

程式啟動時會檢查這幾樣，缺什麼會在紀錄區直接說，並附安裝指令。

## 啟動

按兩下 **`run.bat`**。

或在命令列（在 `py` 資料夾裡）：

```
py -3 anyvideo_download.py
```

## 使用方式

1. **貼上網址**。每行一個，可以一次貼很多個。以 `#` 開頭的行會被略過。
2. 按 **「解析第一個網址」** 可以先看標題、長度與可用畫質（不下載）。
3. 選 **下載類型**：影片，或只要音訊。
4. 選 **格式、畫質、取捨** 與 **儲存位置**。
5. 按 **「開始下載」**。進度、速度、剩餘時間會顯示在下方，詳細過程在紀錄區。

設定會記住，下次開啟沿用。存在 `%APPDATA%\anyvideo_download\settings.json`。

## 支援的輸出格式

### 影片

| 格式 | 說明 |
|---|---|
| **mp4** | 最常用的格式。裡面裝什麼編碼，取決於下面的「取捨」 |
| **mkv** | 什麼編碼都裝得下 |
| **webm** | 開放格式，VP9 / AV1 + Opus |
| **mov** | Apple 生態系。只裝得下 H.264／H.265 + AAC，網站給的是 AV1、VP9 時**會重新編碼** |
| **avi** | 舊式播放器用。**一定會重新編碼**（MPEG-4 + MP3），比較慢 |

畫質可選 最佳、2160p、1440p、1080p、720p、480p、360p。選的是「不超過」這個高度的最佳畫質。

### 取捨：畫質優先 vs 相容優先

同一部影片，網站常常同時提供好幾種編碼。以 YouTube 為例，最高畫質往往只有
**AV1** 或 **VP9**，**H.264** 版本的解析度比較低。兩者只能選一個：

| | 畫質優先（預設） | 相容優先 |
|---|---|---|
| 怎麼挑 | 先比解析度，最高的那個 | 先挑 H.264 + AAC，其中解析度最高的 |
| 常拿到的編碼 | AV1、VP9 | H.264 |
| 能不能播 | 新電腦、新手機沒問題；**舊手機、電視、剪輯軟體常常播不了** | 幾乎到哪都能播 |
| 解析度 | 最高 | 可能比較低（例如 1080p 而不是 4K） |
| 下載速度 | 快 | 通常一樣快；網站**完全沒有** H.264 時要重新編碼，會慢很多 |

**相容優先保證的事**：輸出 mp4、mkv、mov 時，檔案裡一定是 H.264 影像 + AAC（或 MP3）聲音。
網站有 H.264 就直接拿；沒有的話下載完會自動重新編碼，紀錄區會寫
「網站沒有提供相容編碼，重新編碼……」。已經相容的那一邊不會動（例如影像已經是
H.264、只有聲音是 Opus，就只轉聲音）。

webm 與 avi 不受這個保證：webm 規格裝不下 H.264，相容優先時改挑 VP9 + Opus；
avi 本來就一律轉成 MPEG-4。

> **什麼時候會重新編碼？** 原則是能直接封裝就不重新編碼。會重新編碼的情況只有：
> 網站給的編碼放不進你選的容器（例如只有 VP9 卻要 mp4、只有 AV1 卻要 mov）、
> 選了 avi、或選了相容優先而網站沒有 H.264。重新編碼比較慢，而且吃 CPU。

### 音訊

| 格式 | 說明 |
|---|---|
| **mp3** | 最通用 |
| **m4a** | AAC，同位元率下音質比 mp3 好 |
| **opus** | 低位元率時音質最好 |
| **ogg** | Vorbis |
| **flac** | 無損 |
| **wav** | 無損、未壓縮，檔案最大 |

位元率可選 320／256／192／128／96 kbps。flac 與 wav 是無損格式，沒有位元率可選。

## 其他選項

| 選項 | 說明 |
|---|---|
| 下載整個播放清單 | 網址是播放清單時全部下載，存在以清單名稱命名的子資料夾。不勾就只下載網址指向的那一部 |
| 寫入標題等資訊 | 把標題、作者、章節等寫進檔案 |
| 嵌入封面縮圖 | 支援 mp4、mkv、mov、mp3、m4a、opus、ogg、flac。不支援的格式這個選項會自動停用 |
| 嵌入字幕 | 有中文或英文字幕時嵌入影片。支援 mp4、mkv、webm、mov |
| 登入狀態 | 需要登入才能看的內容，借用瀏覽器已經登入的 cookies |
| cookies.txt | 改用匯出的 cookies.txt 檔（「選擇…」挑檔、「清除」取消）。檔案存在時優先於「登入狀態」，也就不必關閉瀏覽器；檔案不見了則忽略，回到「登入狀態」的設定 |

**取消**會在目前這一步結束後停止。未完成的 `.part` 暫存檔會留在資料夾，
下次下載同一個網址會接著下載。

## 「任何平台」實際上是指哪些

**yt-dlp 支援的網站，大約一千八百個**，包含 YouTube、Vimeo、Bilibili、
X（Twitter）、Facebook、Instagram、TikTok、SoundCloud、Twitch 等，以及大部分
直接指向影音檔的網址。完整清單見 yt-dlp 的
[supportedsites.md](https://github.com/yt-dlp/yt-dlp/blob/master/supportedsites.md)。

**下載不了的：**

- **有 DRM 保護的串流服務**（Netflix、Disney+、Spotify、KKBOX 等）。yt-dlp 不破解
  DRM，這個程式也不會。
- **需要登入但沒有提供 cookies 的內容**。在「登入狀態」選一個已經登入該網站的瀏覽器。
  **Firefox 最可靠**；Chrome 新版的 cookies 加密方式有時讀不到，讀取失敗時紀錄區會說明。
  Chrome 讀不到時，也可以用瀏覽器擴充功能匯出 Netscape 格式的 cookies.txt，在「cookies.txt」欄選那個檔案。
- **網站剛改版**。網站改版常讓下載失效，這時按 **「更新下載核心」**，重新開啟程式再試。

請只下載你有權使用的內容，並遵守各平台的使用條款。

## 疑難排解

| 狀況 | 處理 |
|---|---|
| 紀錄區說找不到 ffmpeg | `winget install Gyan.FFmpeg`，裝完**重新開啟**程式 |
| YouTube 下載失敗，或可選畫質很少 | 安裝 deno：`winget install DenoLand.Deno` |
| 某個網站突然下載不了 | 按「更新下載核心」，重新開啟程式 |
| 要登入的影片下載失敗 | 「登入狀態」選 Firefox，並先在 Firefox 登入該網站 |
| 下載的影片在電視、舊手機或剪輯軟體上播不了 | 「取捨」改選**相容優先**，重新下載 |
| 按了 run.bat 沒反應 | 改用 `py -3 anyvideo_download.py` 執行，錯誤訊息會顯示在主控台 |

## 測試

```
py -3 tests\smoke_test.py
```

（在 `py` 資料夾裡執行。）

不開介面、不連任何外部網站：用 ffmpeg 產生一段測試影片，在本機起一個 HTTP 服務，
讓下載核心用正式的程式碼路徑去下載，再轉成每一種輸出格式，最後用 ffprobe 確認
每個檔案的格式與串流都正確。

共 26 項：

| 路徑 | 內容 |
|---|---|
| 單一檔案 → 5 種影片格式 | 網站直接給一個完整檔案 |
| DASH → 5 種影片格式 | 影像與聲音分開，需要合併 —— 主流影音網站的做法 |
| 單一檔案 → 6 種音訊格式 | 轉出音訊 |
| 取捨 → 10 項 | 見下表 |

取捨的測試用了三種來源：只有 AV1 的檔案、只有 VP9 的 webm，以及一份同時提供
AV1 360p 與 H.264 240p 的 DASH（模擬 YouTube 的情況）。

| 項目 | 期望結果 |
|---|---|
| 畫質優先，AV1 → mp4 | 保持 AV1，不重新編碼 |
| 畫質優先，混合 DASH → mp4 | 挑解析度較高的 AV1 360p |
| 相容優先，混合 DASH → mp4 | 直接挑 H.264 240p，不重新編碼 |
| 相容優先，H.264 → mp4 | 原樣保留 |
| 畫質優先，AV1 → mov | mov 裝不下 AV1，重新編碼成 H.264 |
| 相容優先，VP9 webm → mov／mp4 | 重新編碼成 H.264（mp4 先存成 mkv 再改封裝） |
| 相容優先，AV1 → mp4／mkv／mov | 重新編碼成 H.264 |

每一項都會用 ffprobe 檢查影像編碼與解析度，並確認資料夾裡沒有留下中間檔。
